# 加密章节修改难点核查

核查日期：2026-09-08。范围：当前第五章、Code/encry/photo_encry、连接实验脚本与既有记录。后续已处理第1项的正文/实现对齐；原加密实现未改。以下保留原始诊断，并区分已经证实的问题与尚需验证的设计风险。

## 总体判断

主要工作不是补几张安全指标图，而是先统一论文与实现，再证明响应端能独立、可靠地得到所需离散规则，并判断图像结果实际依赖了多少同步信息。目前可以作为待修正的应用原型，尚不能靠文字润色变成可靠的安全加密方案。

## 2. 低同步误差不等于离散密钥一致：核心难点，工作量中到高

例如 0.499 和 0.501 相差只有 0.002，但四舍五入后不同。只有误差小于离量化边界的距离等额外条件，才可从连续误差推导离散一致性。仅设置一个死区参数也不能自动给出全样本的一致保证。

既有 expanded_summary.csv 中，Node 2、名义条件下 PPO 的精确恢复率为约96.7%，而该轮 LQR、SMC 为100%；在 eta=2 时对应 PPO 为75%、LQR为65%、SMC需参考完整表。这说明现有结果既非每次成功，也非 PPO 才能成功。旧连接实验使用 R=1；不能把其结论扩展到最新的已调权重 LQR。

这些是64×64小图、有限取样窗口的旧探索结果，不能当作完整图像尺寸与部署条件下的恢复保证。PPO按三个策略种子、每个20个测试初值评估，汇总先在共同初值内平均策略；旧置信区间反映该汇总口径，不能直接当作独立训练泛化的区间。

对应 R3-4/5、R1-6。需要固定量化流程，报告未筛选试验的规则不一致率、恢复像素/比特误码率和精确恢复率，并区分首次成功率和允许重试后的成功率。

## 3. 滤波和 DNA 组合可能削弱同步的作用：核心难点，已存在直接证据

旧 entropy_check/metrics.csv 的示例中，重复滤波后每条规则流只有一个取值，合并规则流经验熵为0，而 PPO、LQR、SMC 都可恢复图像。这是特定样本的观察，不代表所有生成序列都会塌缩，也不是对整体密码熵的估计。

本次独立16×16合成图诊断进一步验证：四条规则流全为1与四条全为8，产生完全相同的密文；用全8的流可精确恢复由全1流加密的图像。原因是相同规则下的 DNA 编码与解码互逆，两轮可能退化成恒等变换。这里使用人工指定规则流，不是假称实际所有 PPO 序列都如此。

这意味着“恢复成功”单独不足以证明两端规则流相同，更不足以证明 PPO 同步对这次加密不可替代。应增加不相关/固定规则流替换、取消同步控制等功能消融，确认保留下来的同步环节确实参与了加解密。若量化步骤普遍导致退化，需要改方法后重测。

## 4. 图像统计外观与抗攻击能力：难度高，不能仅靠增加指标解决

本次在固定规则流、同一密码下，对明文两个分量作+1/-1改变，使像素总和保持不变；结果密文也只有两个分量改变。因为图像特征只依赖总和，Q不变，而当前 DNA 步骤不跨像素传播变化。这个诊断针对固定提供的规则序列，不是完整的选择明文攻击实现，但已经限制了“微小像素变化全面扩散”的表述。

NPCR、UACI、图像熵、相关性可以补充统计描述，但不能替代密码分析。NIST 对统计测试与密码分析的区别有明确说明：https://csrc.nist.gov/pubs/sp/800/22/r1/upd1/final 。

如保留安全性主张，还需明确攻击者知道什么、每次消息是否更新随机量、是否允许密钥流重复，以及密钥空间在实际浮点实现中的含义。SHA-256被压缩成一个float初值，不等于拥有256位有效初值空间。

## 5. 接收端究竟拿到什么信息：写清楚较容易，证明合理性可能较难

encrypt 返回 (img_word, initial_value)，decrypt 实际使用其中的 img_word 配合密码重新计算初值；正文未清楚定义传递的辅助信息。若把 initial_value 作为公开元数据发出，会暴露该 Logistic 掩码生成所需的初值，因此它的保密地位必须明确。不能把目前函数返回值直接等同于真实通信协议。

同步控制器需要驱动状态/误差信息，必须说明这些信息如何送到响应端、是否保密、是否让第三方也能重建用于编码的驱动序列。当前脚本在同一进程中掌握两套状态，是仿真功能验证，不是完整分布式安全通信实现。

对应 R3-3、R1-6。先画清发送端、接收端、公开通道和秘密参数，再决定是否需要修改接口。

## 6. 成功统计与实验设置还需对齐：中等工作量

- photo_encry 默认生成器目前加载 Node 1，env也默认Node 1；使用 model.predict(obs) 的默认随机策略，暂态1500步且reset未指定种子。
- 连接测试显式配置 Node 2/3，使用确定性预测，默认暂态400步。两套流程不同，不能直接把连接结果当作旧图片的复现。
- 原主流程先比较主从规则流，一次失败可重新生成，最多5次；只展示最终成功的图像会漏掉失败与重试成本。
- decrypt 的返回标志无条件为True。本次错误密码诊断得到True，但逐像素恢复失败；因此应以图像或认证验证作为成功判据，而非这个布尔值。
- 旧加密连接 SAC 使用10万步、一个种子的筛选模型；它不是正文40万余步、三个种子的匹配预算对照，需要更新后才能正式比较。
- 更大图片需要更多序列采样；小图成功不自动保证长序列成功。还需不同图片、长宽和随机种子，且输出应保持无损格式。

## 最小可执行修改顺序

1. 确认合作方要维护的加密实现，以其为准逐式清理正文，先解决流程不一致。
2. 固定模型、节点、确定性动作、种子、暂态和量化流程，重跑不筛选失败的基本恢复测试。
3. 用固定/错误/不相关规则流做功能消融，判断同步对解密的实际作用，并检查量化流多样性。
4. 若前述检查通过，再补参数敏感性、比特误码、不同图像尺寸与控制器比较；最后开展所声称攻击模型下的安全评估。

若保留为同步研究的应用演示，可缩短第五章并限制安全性措辞，但仍必须解决流程一致性和恢复可靠性。若希望把它作为独立的安全加密创新，需要更完整的协议设计与密码分析，不能承诺数天内只靠补图完成。
