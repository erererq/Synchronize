# 离散一致性与DNA抵消：新实验方案

## 交付与范围

- 新实现：`Code/encry/photo_encry_reconciled.py`，可直接运行，也可导入函数。
- 验证：`Code/main/validate_reconciled_encryption.py`。
- 结果：`logs/hopfield/reconciled_encryption/results.json`。
- 原始脚本和 checked 版均保留；论文没有修改。新流程与旧15轮方法不同，旧图表不能直接换标题后使用。

这是一个新增辅助信息的功能实验原型，不是安全密码协议，不是经过安全证明的secure sketch或fuzzy extractor。继续使用旧Logistic掩码只是为了隔离本次修改的效果，不是认可其安全性。

## 1. 为什么相近的数以前会得到不同规则

例如发送端0.49、接收端0.51，误差仅0.02，却在0.5边界两侧。直接取整分别得到0和1。反复滤波可能消除这种差异，但也会把规则流压成常数。

新方案不平滑、不换初值、不重试，而是让接收端知道当前量化格应如何对齐。

## 2. 中心偏移辅助信息

固定量化宽度 Δ=1（预先固定，未根据本次测试误差调大）。对每个发送端样本 x：

```
k = floor(x / Δ + 0.5)
r = x / Δ - k
规则 = (k mod 8) + 1
```

发送端保留整数k，给接收端提供偏移r；r在[-0.5,0.5)内。接收端只用自己的y和收到的r：

```
k_received = floor(y / Δ - r + 0.5)
```

因为 `y / Δ - r = k + (y-x)/Δ`，若 `|y-x| < Δ/2`，再次取整就得到同一个k。这是实数运算下的充分条件；浮点实现须远离边界，不能把恰好等于半格也包括进去。本次实际最大四流误差约0.1265，距0.5有余量。

前面的例子：x=0.49，k=0，r=0.49；y=0.51。接收端先得到0.51-0.49=0.02，再取整为0，和发送端一致。不是把发送端规则直接复制给接收端，也没有使用接收端真值去挑选成功样本。

四条流逐个处理，第四条仍为x1*x2+x3。误差条件必须对四条流都满足，不能只检查原来三维状态中的某一维。规则随原始发送端轨迹变化，不做15轮滤波。

发送端另附整段规则的SHA-256摘要，接收端重建后比较，不一致就拒绝，不输出候选恢复图。这是本地一致性检查，不是认证：没有密钥保护的摘要可以被攻击者替换，也会给低熵规则猜测提供检验条件。

### 不能忽略的代价

- 必须传递并对齐每个样本的偏移；不是完全无通信的同步密钥生成。
- 偏移与原轨迹相关，可能泄露信息；没有证明给出偏移后规则仍保密。
- 规则取模8，若y=x+8Δ，会得到同一规则。这是已验证的别名现象：通过规则摘要不等于连续状态同步。
- 接收端不能凭自己的y、r证明真实误差小于半格；误差上限在当前仿真中由诊断器检查。条件之外可能拒绝，也可能由于模8别名仍通过，不能宣称所有大误差都会被拒绝。
- 这里没有实现辅助信息认证、隐私放大或完整密钥管理。不能直接部署为安全通信。

## 3. DNA不再来回编码解码

旧方案在同一个两比特位置上串联多个编码/解码映射，不同规则组合可能抵消成同一映射。

新方案将每个字节拆成四个两比特位置（从高位到低位），分别由四条规则控制。用A/C/G/T表示0/1/2/3，每条规则是四个符号的一种无不动点排列：每个符号都换成另一符号。共9种这样的排列，固定取字典序前8种，对应规则1到8。

- 第1条流只作用于最高两位，第2条作用于接下来两位，依次类推。
- 解密时，每个位置使用相应排列的逆。
- 四条流不再串联到同一位置，不会彼此抵消。
- 每个位置的8个排列不同，因此8^4=4096种组合对应4096个不同字节查找表。

已穷举4096组，每组全部256字节：全部可逆；无恒等映射，而且各表都没有固定字节。不同映射在某些输入字节上仍可能输出相同值，“查找表不同”不保证任意一张图在任何错误规则下都必定不同。

这是结构清楚的符号置换，不是新的密码安全证明：每块仍然只有4096种候选表，且逐字节局部变换不提供跨像素扩散。DNA名称本身不产生安全性。

## 4. 验证结果

条件：Node 2/3，各训练种子42/123/1024，初值种子100/101/102，名义参数、确定性PPO、暂态1500步；块边长8。图像是固定随机生成器产生的三通道合成图。尺寸共享轨迹前缀，不是独立训练试验。

| 节点 | 图像 | 新映射+直接量化 | 新映射+偏移协调 | 固定全1接收规则替换 |
|---|---|---|---|---|
| Node 2 | 64×64 | 2/9 | 9/9 | 0/9 |
| Node 2 | 128×128 | 0/9 | 9/9 | 0/9 |
| Node 3 | 64×64 | 6/9 | 9/9 | 0/9 |
| Node 3 | 128×128 | 0/9 | 9/9 | 0/9 |

固定替换试验主动绕过摘要检查，并保留相同密码和掩码。因此它不是仅仅因为摘要不匹配而“恢复失败”，而是实际像素无法恢复。另有每次生成独立随机响应流的负对照，36次均被规则摘要拒绝；这不等于训练时无控制器的消融，也不等于攻击评估。

128×128时，发送端每条流平均约3.17种取值，没有被全部压成常数；64×64平均2.25种，短序列个别流仍可能常数。平均不同取值数量不是密码熵估计。

紧凑JSON辅助信息平均约5299字节（64×64）与20744字节（128×128），分别约占未压缩三通道图像字节数的43%和42%；不是相对PNG压缩大小。实际CLI使用缩进JSON会更大。该代价已经不小，未来不能在论文中省略。未经认证的辅助信息不得视作安全公共元数据。

人工边界测试：在固定合成输入上，±0.49Δ扰动全部成功，±0.51Δ被拒绝；+8Δ别名被接受并作为明确局限记录。辅助数据经过JSON序列化再读回参与验证，接收端未直接调用发送端整数数组。

## 5. 使用

在PowerShell中，将INPUT.png改为自己的8位三通道图像，输出目录必须是新目录：

```powershell
E:/Users/anaconda3/envs/lea/python.exe E:/project/Synchronize/Code/encry/photo_encry_reconciled.py --image E:/project/Synchronize/INPUT.png --output E:/project/Synchronize/logs/hopfield/reconciled_run01 --node 2 --model E:/project/Synchronize/models/hopfield/ppo_continuous_hopfield_node2_final_seed_42.zip --seed 100 --burn-in 1500
```

密码通过隐藏输入读取，不记录。输出cipher.png、metadata.json和report.json；通过协调才输出recovered.png。退出码0表示本地逐像素恢复成功，1为规则不一致或恢复失败，2为异常。错误密码不保证在协调阶段拒绝，因为规则摘要不验证密码；最终本地逐像素检查会检查恢复图，这仍不是接收端认证。

复现实验（会覆盖专用验证目录的results.json，不修改模型）：

```powershell
E:/Users/anaconda3/envs/lea/python.exe E:/project/Synchronize/Code/main/validate_reconciled_encryption.py
```

## 6. 对文章意味着什么

可以说：已经构造并验证了一种带辅助信息、具有条件性一致性解释的图像变换原型，并消除了旧映射的组合抵消。

不能说：证明了安全加密、完全不需要通信、PPO独占优势、所有误差下都能恢复，或本次36/36代表部署可靠率。传统控制器如果满足相同误差条件，也能使用此机制。

辅助信息的泄漏与鲁棒性需要独立论证，可参见相关原始研究背景： https://www.iacr.org/archive/eurocrypt2016/96650231/96650231.pdf 。该文献不验证本脚本；本方案没有继承其安全证明。

推荐先与合作方确认是否接受新增通信信息及安全性工作量，再决定进入论文。当前稿子仍描述旧实现，不应直接把新恢复数字放进去。
