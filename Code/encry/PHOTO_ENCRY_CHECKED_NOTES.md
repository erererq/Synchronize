# 加密实验修正版：修改原因与使用说明

日期：2026-09-08。

**后续更新：** 已完成0/1/3/5/15轮对照，新脚本默认改为0轮（直接取整取模，仅用于诊断），旧15轮改为显式 `--filter-passes 15`。这不是已经解决离散一致性的替代算法。新增固定全1接收规则的恢复检查。完整结果与理由见同目录 `QUANTIZATION_PASS_RESULTS.md`。下文关于保留15轮的描述是初版历史记录，默认设置以本段为准；最新回归测试为8项通过。

## 1. 文件与范围

- 新脚本：`Code/encry/photo_encry_checked.py`。
- 回归测试：`Code/main/test_photo_encry_checked.py`。
- 原始 `Code/encry/photo_encry` 保留不动，论文也没有在本次自动改写。

这是实验可靠性修正版，不是新的安全密码方案。新脚本独立实现必要功能，不运行或导入原脚本，不读取其中的硬编码密码。保留原来的 Logistic 掩码、15轮滤波量化和两轮 DNA 映射，便于判断改变是否来自程序修复，而不是偷偷更换算法。

## 2. 为什么这样改

| 原问题 | 修正方式 | 原因 |
|---|---|---|
| decrypt 无条件返回 True | decrypt_image 只返回候选图像；实验主流程用逐像素相等判定恢复 | 没有认证机制时，接收端不能凭一次计算宣称密码正确；本地实验可与原图比较 |
| 像素检查失败仍返回成功 | 记录 recovery_failed，退出码为1；程序异常退出码为2 | 失败必须进入统计，不能只打印警告 |
| 批处理忽略失败、文件存在就跳过 | 当前版本一次运行一个样本，只允许新输出目录 | 防止旧文件被当成新实验成功结果；暂不引入不可靠的批量计数 |
| 重试最多5次后只展示成功 | 每次调用只试一次，记录 attempts=1 | 保留首次失败，避免幸存者偏差；以后批量统计应保留所有 report |
| zip 比较漏掉缺失流，空输入也通过 | 强制4条整数流，每条长度等于块数，取值1到8 | 把输入有效性与相等性分开；坏输入直接报错 |
| 节点模型与环境容易错配 | 必填 --node 与 --model，环境显式设置 node-1；文件名含 node 标记时检查一致性 | 模型维度相同不代表控制节点相同。文件名检查不是训练来源证明，仍须维护模型记录 |
| 随机初值和随机动作不可复现 | 显式 seed，确定性预测，CPU加载；记录节点、模型路径及SHA-256、暂态等 | 支持相同配置复查，不保证跨依赖版本/硬件逐位相同 |
| 超过400步截断仍继续step | 将评估时域明确设为 burn_in+采样数，提前结束则报错 | 连续轨迹不重置，同时避免忽略环境结束状态 |
| 默认参数捕获导致分块设置不同步 | 同一个 block_size 贯穿采样数量、加密、元数据和解密 | 支持边界块，修改块边长不再只改变序列数量 |
| 暗中返回 Logistic 初值 | 元数据只含版本、图像尺寸、块边长、像素和 | 不再导出直接重建掩码的初值；不代表元数据通信协议已安全 |
| 大量二进制字符串和DNA字符逐像素转换 | 用256项字节查找表执行相同映射 | 减少字符串转换；已检查密文兼容性，未做性能加速倍数声明 |
| 看不到量化退化 | 输出每条规则流的不同取值数量、规则不一致率、DNA恒等变换块比例 | 区分“图像恢复”与“同步信息确实参与”；出现常数流时警告 |
| 可能保存有损图像影响验证 | 仅写PNG，写后读回逐像素校验 | 避免JPEG压缩造成实验误差；非uint8三通道输入直接拒绝，不静默转换 |

## 3. 有意没有改动的设计

1. **15轮滤波量化仍保留。** 这是兼容选项，不是认可其合理性；它可能使规则流变为常数。换成另一种量化会改变算法和旧结果，需要后续独立实验。
2. **DNA映射可能相互抵消。** 新代码报告恒等变换块比例，不通过人为调整掩盖问题。
3. **同一个Q用于三个通道，图像特征仍是像素总和。** 没有新增跨像素/跨通道扩散。
4. **没有认证机制。** 错误密码得到候选图像而非可靠的身份/完整性验证。报告中的原图哈希是本地复现实验记录，不是MAC，不应当作公开认证标签。
5. **不写入密码、原始轨迹或规则流。** 若要做接收端独立部署、保存密钥材料或通信协议，须另行设计。

因此：修正版能更诚实地发现失败，但不能保证提高恢复率，更不能据此宣称密码安全。

## 4. 怎么运行

在 PowerShell 中，用现有 lea 环境。将 IMAGE.png 换成真实的8位三通道图像，输出目录必须尚不存在：

```powershell
E:/Users/anaconda3/envs/lea/python.exe E:/project/Synchronize/Code/encry/photo_encry_checked.py --image E:/project/Synchronize/IMAGE.png --output E:/project/Synchronize/logs/hopfield/encryption_checked/node2_seed100 --node 2 --model E:/project/Synchronize/models/hopfield/ppo_continuous_hopfield_node2_final_seed_42.zip --seed 100 --burn-in 1500 --block-size 8
```

运行时隐藏输入实验密码，不把密码放在命令行或报告中。模型必须是对应节点、当前六维全观测环境训练的PPO；部分观测模型不能直接套用。切换节点时同时切换 --node 和 --model。

输出：

- `cipher.png`：密文图像。
- `recovered.png`：候选恢复图，即使恢复失败也保留，不能仅看文件存在判断成功。
- `metadata.json`：解密所需辅助信息，不含浮点初值。
- `report.json`：实际状态、精确恢复、像素分量错误率、比特错误率、规则不一致率及退化诊断。

退出码：0表示本次逐像素恢复且文件读回通过；1表示恢复不一致；2表示运行异常。0不表示安全、规则必然相同或PPO不可替代。命令行参数错误也通常为2；在输出目录建立前的错误不会产生报告。

正式统计应预先确定初值种子列表，收集所有成功、失败和运行错误，不因结果不好反复换种子。当前版本刻意未提供批量筛选功能。

- 用模拟模型输出强制恢复失败，确认退出码1、报告失败，以及拒绝覆盖已有目录。此项不是PPO性能实验。

另加载实际Node 2、seed 42模型，使用测试初值100、20步暂态、4个采样点完成短流程冒烟检查。模型加载和轨迹接口可运行；该短样本规则不一致率为0.25、主从各条流均只剩1个不同取值。暂态刻意很短，不能用它判断正式恢复率或PPO能力，只验证接口及退化报告。

本次没有重新训练模型，没有完成完整图片、多种子恢复率统计，也没有更新论文实验数字。新流程改用了确定性预测，原流程随机动作下的旧图不能直接作为新流程复现结果。

## 6. 下一步顺序

先用真实模型、固定暂态和未筛选初值确认退化程度；再决定是否重做量化和DNA组合。不要在当前原型上先堆叠安全指标，也不要把规则一致率、图像恢复率和同步误差当作同一个指标。
